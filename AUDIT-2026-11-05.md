# AVM code audit, November 5, 2026

Read-only audit of `next` at `55351e8` (after 0.4.36), by five independent reviewers, one per area: VM lifecycle, guest features, security and privacy, the app's interface and accessibility, and tools, tests and QEMU patches. Line numbers are from that commit.

**Status: the nine under "Fix first" are fixed on `next`, except as listed here.** Not fixed: #5's silent tidy-up of the oldest "Before going back" point (intended; still not said aloud); #7's dedicated thread (each reply now has an overall deadline, which bounds the stall); #8's "Finder is in front" trust (no way found to tell a service's real caller; asking for every Finder send would ask about nearly every file). #2's two other questions, Input Monitoring and the helper's approval, now speak themselves instead of waiting; they only open System Settings. The rest of the list is still open.

**Checked by hand against the code:** every finding marked ✓. The rest are as the reviewers traced them, from reading the code. None was run live.

## Fix first

| # | Severity | Where | Problem | Fix |
|---|---|---|---|---|
| 1 | High | `AVM/GuestWatchLogic.swift:446`, `AVM/MachineArchivePanels.swift:214` | ✓ Backup clean-up can delete another machine's backups, for good. All machines back up to one folder, and the clean-up matches names by prefix only. A machine called "Ubuntu" counts "Ubuntu backup backup …" (the backups of a machine called "Ubuntu backup") as its own. They sort after its real ones, so its real backups are the ones deleted, including the one just made. Two names that become the same file name ("Win:11" and "Win-11") delete each other's. `removeItem` skips the Trash. | Match the exact name pattern, or read each package's machine id; move old backups to the Trash |
| 2 | High | `AVM/KeyboardOffer.swift:43`, `VM/VMManager.swift:1598` | ✓ "Use this keyboard for Windows?" can pop up 20 seconds after Windows starts, while the keyboard is in the machine. It isn't spoken, and FocusLock's "another window took the keyboard" stays quiet because a modal is up. "Use for Windows" is the default, so a PIN and Return at Windows' sign-in sets the keyboard as Windows-only. Escape declines it for good. `InputMonitoring.ask` and the helper's approval dialog may do the same. | Don't ask while the keyboard is in a machine; ask once back on the Mac. Make Not Now the default |
| 3 | Medium | `AVM/DescribeScreen.swift:63` | ✓ Describe Screen works with the keyboard in the machine. The first time, with Claude on, its question appears unheard, and the default button is "Send, and Don't Ask Again". Pressing Return to try again sends the screen to Anthropic and remembers that for good. | Speak the question or leave the machine first; make "Use the Mac Only" the default |
| 4 | Medium | `views/SetupView.swift:899`, `VM/VMManager.swift:2402, 3834`, `AVM/MachineArchive.swift:216, 654` | ✓ A machine in a folder the user chose can be read by every account on the Mac: its folder is 0755, `disk.qcow2` and `nvram.fd` are 0644 (seen on the test machine), and the TPM state is group-readable. Backups and exports copy those modes. A screen picture (`watch-screen.ppm`) also sits there while the machine runs. A pre-made "AVM Virtual Machines" in `/Users/Shared` is accepted from another owner. Machines in Application Support are protected by the home folder. | Create machine folders and `tpm-state` 0700, files 0600; refuse a parent folder owned by someone else; same for backups |
| 5 | Medium | `views/SettingsView.swift` restore flow (`55351e8`), `VM/VMStore.swift:727, 750` | Restore points, new today: ✓ renaming a "Before going back" point leaves its tidy-away mark, so AVM still deletes it after two more restores, even though the rename shows the user wants it. ✓ Save a Restore Point while running doesn't check that the machine can save (an NVMe or 3D machine always fails) and doesn't mark the list busy, so Restore can force-stop the machine mid-save. A running restore can also miss a saved state still on the disk (a Save or a resume under way), and the next Start loads that instead. A restore that fails after turning the machine off says only "not restored", not that it's now off. Quit doesn't ask while a restore is under way. | Rename removes the marks; gate on `canSave` and set busy; refuse while saving and discard any saved state; say the machine is off; ask before quitting |
| 6 | Medium | `Tools/publish-release.sh:96-124` | ✓ Finishing a draft release never checks its target commit, so GitHub can tag a different commit from the one the files were built from: the mismatch the sixth audit's check exists to stop. `--early` is also ignored on an existing release, so an early build becomes "Latest". | Refuse unless the draft's target is the built commit, or set `--target`; pass `--prerelease` on edit |
| 7 | Medium | `AVM/GuestAgent.swift:83-97`, `VM/VMManager.swift:4824` | A guest agent that sends a byte every few seconds keeps a call going indefinitely: each read has a timeout, the call doesn't. It holds the machine's agent lock and a thread of Swift's small shared pool, so one or two such guests can stall AVM's async work for every machine. | An overall deadline per call; a dedicated thread for the agent |
| 8 | Medium | `AVM/SendToMachine.swift:56` | ✓ The Nov 1 send-file fix can be bypassed. The protected-folder check compares path text, so `/System/Volumes/Data/Users/<you>/Documents/…` gets no question (and plausibly a differently-cased path), and AVM reads the file with its own permissions. "Finder is in front" is taken as proof the request came from Finder. | Compare real file identities, not path text; don't trust the frontmost app |
| 9 | Medium | `AVM/MachineArchivePanels.swift:396, 405` | Import checks the package's disk for references to outside files, then copies it. A package on a drive someone else controls can swap the disk in between, and QEMU then opens a Mac file with AVM's rights. | Check the copied folder, before saving the configuration |
