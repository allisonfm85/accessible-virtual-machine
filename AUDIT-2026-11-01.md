# AVM code audit, November 1, 2026

Read-only audit of `next` at `f238ddd` (version 0.4.20) by five independent reviewers, one per area. Nothing has been fixed yet. Line numbers are from that commit.

**Checked by hand against the code:** every finding marked ✓. The rest are as the reviewers traced them, from reading the code. None was run live, unless it says so.

## Fix first

These are the ones I'd fix before anything else.

| # | Severity | Where | Problem | Fix |
|---|---|---|---|---|
| 1 | High | `Announcer.swift:392` | ✓ Every spoken line is logged whole, including text read from a machine's screen. A password or document shown on screen ends up in the log that Report a Problem sends, despite comments saying it isn't logged. | Log a count or placeholder for screen text |
| 2 | High | `AVM/MachineArchive.swift:177`, `AVM/MacAutoSetup.swift:48` | ✓ `mac-setup.json` holds the macOS account password in plain text and isn't excluded from export. | Add it to `importSkips` |

The root helper's checks hold up, and no way was found for a guest to run code on the Mac.

| # | Severity | Where | Problem |

## Found during today's run, not by the audit

- **Windows froze twice at boot, unexplained.** With ten machines installing at once, a Windows install froze at the same kernel spot, including after a reset. Two fresh installs alone passed, including one with 0.4.18's QEMU, so October 31's QEMU patch is cleared. The frozen state is kept in `~/Library/Caches/AVM-build/hang-state-20261101`.
- **Read Screen is probably black on Linux 3D machines today.** QEMU's screenshot is black once the graphics chip draws. The fix is on the `windows-3d` branch, tested on Windows; not yet tried on Linux 3D.
