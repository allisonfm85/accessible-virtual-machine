# AVM code audit, November 5, 2026, second pass

Read-only audit of `main` at `1304456` (0.4.37, as published), by five independent reviewers cutting the code differently from the morning's audit (AUDIT-2026-11-05.md): today's changes with fresh eyes, concurrency and lifetime across the app, the install pipelines and everything put inside a guest, the helper and native code, and data integrity. Line numbers are from that commit.

**Status: fixed on `next` after 0.4.37, except as listed here.** Not fixed: the LLVM and gettext dylibs the app ships (helper section): pruning by linked libraries would drop the GStreamer and ANGLE libraries QEMU opens by name at run time, so it needs a live test matrix first; a key held down at the moment the helper seizes a keyboard (not reproduced); `endQEMUAndWait`'s 2 s per hung machine at Quit Now (by design; still unannounced); backup packages whose manifest can't be read are still never tidied (AVM can't tell whose they are); #12 records the drive's UUID and finds a drive mounted under another name, but there is no "Locate folder" action; #22's login-window recognition is replaced by a "setup begun" mark, so a cut-short automatic macOS setup never runs twice. The HID bridge's feature GET_REPORT is built on both sides and QEMU rebuilt, but no Bluetooth braille display was tried.

**Checked by hand against the code:** findings marked ✓. The rest are as the reviewers traced them. None was run live.

**One finding withdrawn:** the first reviewer reported that the restart after a running restore uses a stale configuration and the wrong disk bus (High). It doesn't: `saved` in SettingsView is computed from the store on every read, and `VMStore.save` updates the list synchronously, so the restart sees the corrected bus. Recorded here so it isn't raised again.

## Helper and native code

Nothing High. The helper's ownership, release paths and peer checks held up. Items: usb-hid-bridge can't answer a feature GET_REPORT (a Bluetooth braille display may enumerate in Windows but never be driven; needs a request/reply frame pair); an idle-exit race can drop a just-accepted XPC call; Bluetooth relay does blocking I/O on the one shared queue; keys from a just-released keyboard still reach the guest until the cancel handler runs; `restart` exits with another user's USB device attached; the app ships ~25 MB of LLVM and gettext dylibs nothing links; `usbstream.c` opens the device before verifying the socket peer (harmless, momentary).

## Concurrency, smaller

`WindowsKeyboard.releaseHeldKeys` awaits a whole chain of 5 s sends before a save can fail; `sampleQEMUCPUPercent` waits before draining (a few bytes, no deadlock today); `endQEMUAndWait` blocks the main thread 2 s per hung machine at Quit Now with nothing said.

## Today's changes, smaller

`waitUntilDiskIsFree` sees only QEMU's lock, which some SMB/FUSE mounts don't support; the whole-line agent deadline caps a reply at 10 s × throughput (a very chatty guest-exec could be cut off); a home folder on another volume makes Send File ask for every file; a stopped machine waiting on a point gets no undo box and no explanation; renaming an automatic point stops its replacement, which the Rename alert doesn't say; Delete while the machine stops under the question gives qemu-img's words rather than "stopped while you were asked".

## Checked and found sound

The saved-state marker/hint/note protocol in every path; `configurations.json` written atomically and never overwritten while unreadable; delete files-first and refusing while running; QMP reply matching, teardown and job cancellation; `VMManager.deinit` unreachable with a live QEMU; every `assumeIsolated` on the main run loop; observers removed with their owners; per-machine keying for two running machines; sleep/wake with saves; every answer-file value escaped for its language; reinstall guards; download verification; the helper's XPC decoders, socket checks and device lifetime; the QEMU patches' vmstate and locking; build signing and entitlements; and today's restore-point, backup and send-file changes apart from the items above.
